Le concept

Anatomie d'un plugin
Grasshopper

Comment Grasshopper trouve ton code au démarrage, et comment une classe C# devient un composant posé sur le canvas.

50 min de lecture et de QCM Prérequis · 02 héritage · 04 .NET et assemblies · 05 csproj Exemple · Cuttlefish

L'idée en une phrase

Un plugin Grasshopper est une DLL .NET renommée en .gha. Au démarrage, Grasshopper l'ouvre, y cherche les classes qui héritent des types de son SDK, et fait de chacune un composant.

L'analogie

Une prise normalisée. Grasshopper fournit la prise : des classes de base, avec des méthodes à redéfinir. Ton plugin fournit l'appareil, qui fonctionne parce qu'il en respecte la forme.

À la fin, tu sais

  1. reconnaître les trois classes d'un plugin et le rôle de chacune ;
  2. relier chaque partie visible d'un composant à la ligne de code qui la définit ;
  3. prévoir combien de fois Grasshopper appellera ton calcul, selon l'accès item, list ou tree.
À retenir Grasshopper appelle, ton code répond. Tu n'appelles jamais SolveInstance toi-même : c'est Grasshopper qui décide quand calculer. On appelle ce principe l'inversion de contrôle.

Schéma 3 · Le mode d'accès

Item, list ou tree : combien d'appels à SolveInstance ?

Le dernier argument de chaque Add…Parameter décide de ce que reçoit SolveInstance, et donc du nombre de fois où Grasshopper l'appelle. Même entrée dans les trois cas : trois nombres 0,5 · 1 · 2.

Pourquoi Bubble prend ses points en tree Pour dessiner une bulle, il faut connaître la distance au plus proche voisin. Ce voisin peut se trouver dans n'importe quelle branche : le composant doit donc voir tous les points en même temps. Le commentaire est dans le code : « Le plus proche voisin est cherché parmi tous les points de l'arbre. »
Piège courant Mélanger les accès. Si Factor reçoit trois valeurs et Points un arbre, Grasshopper appelle SolveInstance trois fois, et relit l'arbre complet à chaque fois. Le résultat est juste, mais le calcul est fait trois fois.

Aide-mémoire et glossaire

Glossaire

.gha
Une DLL .NET que Grasshopper charge comme bibliothèque de composants.
GH_AssemblyInfo
La carte d'identité de la bibliothèque : nom, icône, auteur, Guid.
GH_AssemblyPriority
Le code exécuté au chargement, avant les composants.
GH_Component
La classe de base de tout composant.
SolveInstance
La méthode de calcul ; Grasshopper l'appelle, jamais toi.
IGH_DataAccess (DA)
Le guichet unique pour lire les entrées et écrire les sorties.
GH_ParamAccess
Le mode d'accès d'une entrée : item, list ou tree.
Guid
Un identifiant unique et permanent, écrit dans chaque fichier .gh.
Inversion de contrôle
Le cadre appelle ton code au moment qu'il choisit.
