Le concept

L'écosystème des plugins Grasshopper

Grasshopper seul fait beaucoup ; ses plugins font le reste : physique, climat, structure, maillages. Les installer est facile. Les choisir, les garder à jour et partager un fichier qui en dépend demande de savoir où ils vivent et ce que le fichier .gh retient d'eux.

50 min de lecture et de pratique Niveau · débutant à intermédiaire Prérequis · 7 Exemples · Package Manager, Food4Rhino, Libraries

L'idée en une phrase

Un plugin est une dépendance : le fichier .gh ne garde que son nom, son identifiant et sa version. Celui qui ouvre le fichier doit avoir le même plugin, installé depuis une source sûre.

La situation

Une définition envoyée à un collègue s'ouvre chez lui avec des composants rouges et un message d'objets non reconnus. Il lui manque Pufferfish. Installé par le Package Manager dans la même version, le fichier s'ouvre comme chez toi.

À la fin, tu sais

  1. installer un plugin par le Package Manager ou à la main ;
  2. savoir où il est rangé et comment Grasshopper le reconnaît ;
  3. comprendre ce qui se passe quand un plugin manque ;
  4. choisir un plugin pour un projet qui dure.
À retenir Le Package Manager installe des versions identifiées, par version de Rhino ; un .gha copié à la main va dans Libraries, après déblocage. Le .gh retient le GUID et la version de chaque composant : sans le plugin, il s'ouvre avec des objets non reconnus.

Schéma 1 · Installer

D'où viennent les plugins

Depuis Rhino 7, la plupart des plugins se trouvent dans le Package Manager, le gestionnaire de paquets de Rhino (Yak). Food4Rhino, la vitrine des plugins, renvoie souvent vers lui. Le .gha copié à la main reste possible.

Repère · trois chemins d'installationPackageManager chercher, installer, mettre à jour, désinstaller Food4Rhino fiche du plugin, documentation, lien de téléchargement Components Folder File › Special Folders : y copier un .gha débloqué

Le Package Manager

Il range chaque paquet par version de Rhino et par version du plugin. Il sait ce qui est installé, propose les mises à jour et désinstalle proprement.

Le .gha à la main

Un fichier téléchargé depuis Internet peut être bloqué par Windows : Propriétés › Débloquer, puis copie dans Libraries et redémarrage.

Piège courant Installer le même plugin des deux façons. Deux copies chargées à deux endroits entrent en conflit, et l'on ne sait plus laquelle répond. On garde une seule source.

Schéma 2 · Le fichier

Ce que le .gh retient

Le fichier .gh ne contient pas le code des plugins. Pour chaque composant, il enregistre son identifiant, la bibliothèque d'où il vient, sa version et ses réglages. À l'ouverture, Grasshopper recrée le composant d'après cet identifiant.

Repère · avant d'envoyer un fichier1. lister les plugins utilisés et leurs versions 2. les écrire dans le fichier (Scribble ou Panel) ou dans le message 3. pour une fonction simple, préférer un composant natif ou un script

Quand un plugin manque

Le fichier s'ouvre quand même. Les composants absents deviennent des objets non reconnus, et le dialogue qui s'affiche nomme le plugin à installer.

Les objets utilisateur

Un cluster ou un composant réglé peut être enregistré en objet utilisateur (.ghuser). Lui aussi dépend des plugins qu'il contient.

Piège courant Renommer ou réinstaller un plugin « équivalent » en espérant que le fichier s'y retrouve. Seul l'identifiant compte : un autre plugin aux composants homonymes ne les remplace pas.

Schéma 3 · Choisir

Un plugin pour un projet qui dure

Un plugin ajouté à une définition devient une dépendance pour tous ceux qui l'ouvriront, et pour toi à chaque mise à jour de Rhino. On le choisit comme une bibliothèque de code.

Repère · les questions à se posermaintenu ? dernière version, compatible avec ta version de Rhino licence ? gratuit, commercial, conditions d'usage nécessaire ? un composant natif ou un script suffirait-il ? partageable ? tes destinataires pourront-ils l'installer ?

Rhino 8 et .NET

Rhino 8 tourne par défaut sur un .NET récent. Un plugin ancien, compilé pour .NET Framework, peut ne pas se charger ; la commande SetDotNetRuntime permet de revenir à l'ancien environnement.

Le forum et la documentation

Un plugin vivant a des exemples, une documentation et des réponses sur le forum de McNeel. C'est souvent le meilleur indice de sa durée de vie.

Piège courant Construire une définition centrale sur un plugin abandonné. À la prochaine version de Rhino, il ne se charge plus, et toute la chaîne s'arrête avec lui.

Mise en pratique

Installer, perdre, retrouver un plugin

Tu installes un plugin, tu l'utilises dans une définition, puis tu le retires pour voir ce que voit un collègue qui ne l'a pas.

Exercice guidé

  1. Dans Rhino, PackageManager : cherche un petit plugin gratuit (par exemple Pufferfish), installe-le, redémarre Rhino.
  2. Dans Grasshopper : File › Special Folders › Components Folder. Note le chemin, puis repère le nouvel onglet.
  3. Pose un composant du plugin, relie-le à une géométrie simple, et enregistre le fichier.
  4. Dans PackageManager, onglet des paquets installés : désinstalle le plugin, puis redémarre Rhino.
  5. Rouvre le fichier et lis le dialogue affiché.
  6. Réinstalle le plugin, redémarre, rouvre le fichier.
Résultat attendu Sans le plugin, le fichier s'ouvre avec un dialogue d'objets non reconnus qui nomme le plugin manquant ; ses composants ne calculent plus. Une fois le plugin réinstallé, le fichier se rouvre comme avant : les composants retrouvent leurs réglages, puisqu'ils sont stockés dans le .gh.
Défi Prépare ce fichier pour un collègue qui n'a jamais utilisé ce plugin, sans lui envoyer autre chose que le .gh.

Chaque plugin déclare ses informations dans une classe unique. Celle de Cuttlefish montre ce que Grasshopper affiche et ce qu'il utilise pour le reconnaître.

Vérifie ton travail

  • ☐ Tu sais dire dans quel dossier le plugin s'est installé.
  • ☐ Le dialogue d'ouverture nomme bien le plugin retiré.
  • ☐ Les réglages du composant sont revenus après réinstallation.
  • ☐ Tu n'as qu'une seule copie du plugin installée.

Repères

Aide-mémoire et glossaire

En résumé

Un plugin s'installe par le Package Manager, qui range des versions identifiées par version de Rhino, ou à la main dans Libraries après déblocage. Le .gh retient l'identifiant, le nom et la version de chaque composant, jamais son code : sans le plugin, il s'ouvre avec des objets non reconnus. On choisit un plugin comme une bibliothèque : maintenu, sous licence claire, et seulement s'il est utile.

Le défi, une solution

Ajoute dans le fichier un Scribble ou un Panel bien visible : le nom du plugin, sa version, la façon de l'installer (Package Manager) et la version de Rhino utilisée. Si le composant ne fait qu'une opération simple, remplace-le par des composants natifs ou un petit script : le fichier n'a plus de dépendance.

Glossaire

Plugin (.gha)
Une assembly .NET qui ajoute des composants à Grasshopper.
Package Manager (Yak)
Le gestionnaire de paquets de Rhino : versions, installation, mise à jour.
Libraries
Le dossier où Grasshopper charge les .gha installés à la main.
Objet non reconnu
Un composant dont le plugin manque à l'ouverture du fichier.
Objet utilisateur (.ghuser)
Un composant ou cluster réglé, enregistré pour être réutilisé.
