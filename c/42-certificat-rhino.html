Le concept

Le certificat, un document Rhino sans fenêtre

À la fin d'un parcours validé, Magpie remet un certificat PDF. Il n'utilise pour cela ni Word ni bibliothèque PDF : il ouvre en coulisse un document Rhino invisible, y remplit quelques textes nommés, et imprime la mise en plan. Rhino sert ici de moteur de mise en page.

45 min de lecture et de QCM Prérequis · 37 et 41 Exemples · Core/MagpieCertificateGenerator.cs, Core/TrainingManager.cs (Magpie)

L'idée en une phrase

Le gabarit est un fichier .3dm dessiné dans Rhino ; le code n'en connaît que les noms de quelques objets texte, et il remplace leur contenu avant d'en faire une page PDF.

L'analogie

Un formulaire imprimé avec des cases étiquetées. Le graphiste dessine le formulaire comme il veut ; le secrétariat ne fait que remplir les cases « Nom », « Date », « Parcours », sans jamais toucher au dessin.

À la fin, tu sais

  1. ouvrir un document Rhino sans fenêtre, et le refermer ;
  2. retrouver un objet par son nom et changer son texte ;
  3. distinguer un champ obligatoire d'un champ facultatif ;
  4. dire quand le certificat est produit, et qui le produira demain.
À retenir Le document actif de l'utilisateur n'est jamais touché : RhinoDoc.CreateHeadless ouvre un second document, sans vue à l'écran, qui vit le temps de produire le PDF puis est refermé dans un finally (MagpieCertificateGenerator.cs, lignes 55–57 et 90–96).

Schéma 1 · Le gabarit et ses champs

Des objets texte qui portent un nom

Dans le gabarit, chaque texte à remplir est un objet texte ordinaire de la mise en plan, dont la propriété Nom (celle du panneau Propriétés de Rhino) vaut Magpie_Nom, Magpie_Parcours… Le reste de la page, cadre, logo, phrases fixes, le code l'ignore.

Core/MagpieCertificateGenerator.cs · 15–29// Convention de nommage des objets texte du gabarit - un seul // endroit où ces noms sont écrits en dur. private const string FieldNom = "Magpie_Nom"; private const string FieldParcours = "Magpie_Parcours"; private const string FieldDate = "Magpie_Date"; private const string FieldStatut = "Magpie_Statut"; … private const string FieldNumero = "Magpie_Numero";

Un nom, pas une position

Le code ne dit jamais « le texte en haut à gauche ». Le graphiste peut déplacer, agrandir ou changer la police d'un champ dans Rhino : tant que l'objet garde son Nom, le certificat suit, sans recompiler une ligne.

Trois obligatoires, deux facultatifs

Nom, parcours et date sont exigés : leur absence lève une erreur qui dit quoi vérifier (lignes 100–106). Statut et numéro sont facultatifs : absents, on passe (lignes 109–112), pour qu'un ancien gabarit marche encore.

Piège réel Exiger un champ que le gabarit n'a pas. Le gabarit livré ne contient aucun objet Magpie_Statut : l'exiger comme les trois autres ferait échouer toute génération. Il est donc facultatif, et l'ajouter au gabarit suffira à faire apparaître la mention (lignes 65–69).

Schéma 2 · Un document en coulisse

Ouvrir, remplir, imprimer, refermer

Le gabarit voyage dans le binaire, comme ressource embarquée. Rhino ne sait pas ouvrir une ressource : il faut d'abord la recopier dans un vrai fichier, puis l'ouvrir en document sans fenêtre.

Core/MagpieCertificateGenerator.cs · 53–96string templatePath = ExtractTemplateToTempFile(); RhinoDoc doc = RhinoDoc.CreateHeadless(templatePath); try { SetTextField(doc, FieldNom, nom); … var pageViews = doc.Views.GetPageViews(); … var pdf = Rhino.FileIO.FilePdf.Create(); var captureSettings = new Rhino.Display.ViewCaptureSettings(pageViews[0], 300); // 300 dpi pdf.AddPage(captureSettings); pdf.Write(outputPath); return outputPath; } finally { doc.Dispose(); }

D'où vient le gabarit

Tout ce qui est sous plugin\Resources\ est embarqué par un glob (Magpie.Core.csproj, ligne 36). Le gabarit y est sous le nom Magpie.Resources.certificate_template.3dm (ligne 13), recopié dans %TEMP%\magpie_certificate_template.3dm (ligne 138), écrasé à chaque fois.

La première mise en plan

Le PDF reçoit une seule page : la capture de pageViews[0], à 300 points par pouce. Un gabarit sans mise en plan est refusé avec un message clair (lignes 74–76). Le fichier part dans Certificats\ du dossier de travail (lignes 78–81).

Piège courant Oublier de refermer le document sans fenêtre. Rien ne le montre à l'écran : s'il n'est pas libéré, il reste ouvert, invisible, jusqu'à la fermeture de Rhino (commentaire des lignes 92–94). D'où le finally, qui le referme même quand un champ manque.

Schéma 3 · Quand le certificat naît

Jamais au prix de l'écran de fin

Le certificat est produit par CompleteParcours, au dernier exercice. Deux règles l'encadrent : pas de certificat sous le seuil de réussite, et aucun échec de génération ne doit priver l'apprenant de son écran de fin.

Core/TrainingManager.cs · 203–221// Pas de certificat sans parcours validé (décision de Jérémy, 20/10/2026) : le // gabarit atteste « a suivi avec succès », ce qui serait faux en deçà du seuil. if (!IsParcoursValidated) { _certificateError = $"parcours non validé (seuil de {_successThreshold:P0} non atteint)"; } else try { …Generate(UserName, _parcoursTitle, maintenant, ValidationLabel, _lastCertificateNumber); } catch (Exception ex) { _certificateError = ex.Message; }

Un numéro lisible, pas un registre

NouveauNumero forme GH-AAAA-MMJJ-XXXX : la date, puis quatre caractères tirés d'une empreinte SHA-1 du nom, du parcours et de l'instant (lignes 38–46). Deux apprenants du même jour n'ont pas le même numéro ; mais personne ne peut encore le vérifier.

Demain, sur le site

Le modèle de diffusion (§ 7) confie le certificat au site : gabarit PDF à champs nommés, rempli par pdf-lib, numéro adossé à une page publique de vérification. Les mêmes noms de champs ; un autre moteur. Le générateur Rhino reste jusqu'à la bascule.

Piège réel Se fier à un numéro de ligne cité dans une doc. Le § 7 du modèle de diffusion renvoie à TrainingManager.cs:172 pour l'appel du certificat ; le code a bougé depuis, l'appel est aux lignes 212–214. Cite le nom de la méthode, CompleteParcours, qui lui ne bouge pas.

Glossaire

Document sans fenêtre
Un RhinoDoc ouvert par CreateHeadless, sans vue à l'écran, à refermer soi-même.
Mise en plan
La page d'un document Rhino (layout), avec ses détails et ses textes, prête à imprimer.
Gabarit
Le document modèle dont on ne change que des champs nommés.
Champ nommé
Un objet texte du gabarit repéré par sa propriété Nom, pas par sa position.
Ressource embarquée
Un fichier rangé dans le binaire, lu par GetManifestResourceStream.
