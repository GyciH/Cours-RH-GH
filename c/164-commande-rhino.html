Le concept

Une commande Rhino

Grasshopper n'est pas la seule façon d'automatiser Rhino. Une commande, c'est le geste le plus naturel de Rhino : un nom tapé, quelques questions à la ligne de commande, et le document change. En écrire une, c'est respecter ce dialogue que tout utilisateur connaît.

50 min de lecture et de pratique Niveau · intermédiaire Prérequis · 9, 157 Exemples · RhinoCommon, Script Editor, GetPoint

L'idée en une phrase

Une commande est une classe que Rhino appelle par son nom ; elle demande ce qu'il lui faut à la ligne de commande, modifie le document, puis dit si elle a abouti. Rhino s'occupe de l'annulation et de la répétition.

La situation

Chaque jour, un plateau de 1200 × 800 × 25 mm se dessine en quatre commandes et autant de coordonnées. Une commande Plateau demande un coin, propose la largeur et la profondeur en options, et pose le volume. Ctrl+Z l'annule d'un geste.

À la fin, tu sais

  1. décrire le trajet d'une commande, du nom tapé au document modifié ;
  2. demander un point, un objet, une option, et traiter Échap ;
  3. respecter les conventions de la ligne de commande ;
  4. essayer une commande depuis le Script Editor de Rhino 8.
À retenir Une commande : RunCommand reçoit le document, demande ses saisies par des invites, ajoute ou modifie des objets, redessine, puis rend Success ou Cancel. Chaque invite peut rendre un point, une option, une annulation ou rien : on traite chaque cas.

Schéma 1 · Le squelette

Du nom tapé au document modifié

Une commande RhinoCommon dérive de la classe Command. Elle déclare son nom anglais et écrit RunCommand, que Rhino appelle avec le document actif. Le plugin (.rhp) qui la contient est chargé une fois ; ses commandes deviennent alors disponibles.

Exemple autonome · C#, le squelette d'une commandepublic class PlateauCommand : Command { public override string EnglishName => "Plateau"; protected override Result RunCommand(RhinoDoc doc, RunMode mode) { if (RhinoGet.GetPoint("Coin du plateau", false, out Point3d coin) != Result.Success) return Result.Cancel; var b = new Box(new Plane(coin, Vector3d.ZAxis), new Interval(0, 1200), new Interval(0, 800), new Interval(0, 25)); doc.Objects.AddBrep(b.ToBrep()); doc.Views.Redraw(); return Result.Success; } }

Le document reçu

RunCommand reçoit le document sur lequel travailler : on ajoute par doc.Objects, on lit les unités et la tolérance dans le document, jamais dans des valeurs codées en dur.

Le résultat rendu

Success dit que la commande a abouti ; Cancel qu'elle a été abandonnée. L'historique, la répétition et les scripts s'en servent.

Piège courant Oublier doc.Views.Redraw(). Les objets sont bien dans le document, mais la vue ne les montre qu'au prochain rafraîchissement : on croit que la commande n'a rien fait et on la relance.

Schéma 2 · Demander

Les invites et leurs résultats

Pour demander un point, un objet, un nombre, RhinoCommon fournit des invites (GetPoint, GetObject, GetNumber). Elles affichent un message, des options cliquables, et rendent un résultat qu'il faut examiner.

Exemple autonome · C#, une option dans une invitevar gp = new GetPoint(); gp.SetCommandPrompt("Coin du plateau"); var largeur = new OptionDouble(1200); gp.AddOptionDouble("Largeur", ref largeur); while (true) { GetResult r = gp.Get(); if (r == GetResult.Option) continue; // l'option a changé : on redemande if (r != GetResult.Point) return Result.Cancel; // Échap ou autre break; }

Des valeurs par défaut

Une option affiche sa valeur courante : Entrée l'accepte. L'utilisateur qui tape la même chaque jour ne tape plus rien.

Choisir un objet

GetObject filtre par type (courbe, surface…) et peut accepter une présélection : l'utilisateur qui a déjà sélectionné n'a pas à recommencer.

Piège courant Ne tester que le cas « point ». Si l'utilisateur clique une option ou appuie sur Échap, le code continue avec un point vide, à l'origine, et ajoute un objet au mauvais endroit.

Schéma 3 · Les conventions

Ce que l'utilisateur attend

Un utilisateur de Rhino a des réflexes : Entrée pour valider ou répéter, Échap pour sortir, des options à la ligne de commande, Ctrl+Z pour tout annuler. Une commande qui les respecte s'apprend sans mode d'emploi.

Repère · essayer sans Visual Studio (Rhino 8)ScriptEditor ouvrir l'éditeur, nouveau script C# F5 exécuter le script dans le document courant projet du Script Editor publier les scripts comme commandes d'un plugin

Une annulation par commande

Rhino ouvre un enregistrement d'annulation avant RunCommand et le ferme après : tout ce que la commande a fait s'annule d'un seul Ctrl+Z.

Scripts et macros

Les commandes s'enchaînent dans des macros (_Plateau _Enter) et des scripts. Une commande qui pose ses questions par la ligne de commande s'y prête naturellement.

Piège courant Ouvrir une fenêtre pour chaque valeur. La commande devient lente au clavier, et impossible à piloter depuis une macro : on garde les fenêtres pour les réglages complexes.

Mise en pratique

Un plateau en une commande

Tu écris dans le Script Editor de Rhino 8 un script qui se comporte comme une commande : il demande un coin, propose une option et pose un plateau.

Exercice guidé

  1. Fichier en millimètres. Lance ScriptEditor, crée un script C#.
  2. Recopie le corps de RunCommand du schéma 1 : ajoute var doc = RhinoDoc.ActiveDoc; au début, et remplace chaque return … par return;
  3. Exécute (F5), clique un point dans la vue Dessus.
  4. Relance, puis appuie sur Échap à l'invite.
  5. Remplace RhinoGet.GetPoint par la boucle du schéma 2, et utilise largeur.CurrentValue pour l'intervalle en X.
  6. Exécute, choisis l'option Largeur, tape 1500, puis clique un point.
Résultat attendu Au premier essai, un plateau de 1200 × 800 × 25 mm apparaît, son coin au point cliqué. Avec Échap, rien n'est ajouté. Avec l'option, la ligne de commande affiche Largeur=1500 et le plateau fait 1500 mm de large.
Défi Transforme le script : au lieu d'un coin, il demande une courbe plane fermée et l'extrude de 25 mm, en refusant tout autre type d'objet.

Dans tes projets

SnapSet n'a pas de commande, mais suit la même règle : un message pour l'utilisateur passe par la ligne de commande, pas par une fenêtre qui interrompt.

Vérifie ton travail

  • ☐ Le plateau est posé exactement au point cliqué.
  • ☐ Échap n'ajoute rien au document.
  • ☐ L'option affiche sa valeur courante à l'invite.
  • ☐ La vue montre le plateau sans avoir à la rafraîchir.

Aide-mémoire et glossaire

En résumé

Une commande RhinoCommon dérive de Command, déclare son nom et écrit RunCommand, qui reçoit le document. Elle demande ses saisies par des invites dont elle traite chaque résultat (point, option, annulation, rien), ajoute ses objets par doc.Objects, redessine et rend Success ou Cancel. Rhino lui offre l'annulation d'un geste, la répétition et l'appel par macro.

Le défi, une solution

RhinoGet.GetOneObject("Contour du plateau", false, ObjectType.Curve, out ObjRef r) ; si le résultat n'est pas Success, on sort. r.Curve() donne la courbe ; si elle n'est ni fermée ni plane, on écrit un message et l'on sort. Sinon Extrusion.Create(courbe, 25, true) crée un volume fermé, ajouté par doc.Objects.AddExtrusion, puis Redraw.

Glossaire

Commande
Une classe que Rhino appelle quand l'utilisateur tape son nom.
Invite
Une question posée à la ligne de commande, avec options.
Option de commande
Un réglage cliquable ou tapé sans quitter la commande.
Plugin Rhino (.rhp)
Une assembly qui ajoute des commandes à Rhino.
Résultat de commande
Success, Cancel… : ce que la commande rend à Rhino.
